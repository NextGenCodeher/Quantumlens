Quantum Lens Documentation

Quantum Lens is an interactive toolkit for building, visualising and analysing quantum circuits. On top of the original home page, tutorials, Celestial Toolkit simulators and Quantum Assistant chatbot, it now includes an AI-powered quantum learning platform: structured modules, a drag-and-drop circuit builder, a multi-framework code lab, multi-backend simulation, rich visualisations, an AI tutor, assessments, progress tracking, personalised learning paths and an instructor dashboard.

Where things are: Learn (modules, quizzes, learning path) · Lab (builder, code lab, backends, visualisations, challenges, saved circuits, tutor) · Dashboard (learner progress & instructor analytics) · Delivery Table.

Getting started

Option A — no install. Open index.html in a browser (or host the folder on any static web server). Everything works using the built-in JavaScript statevector engine; progress and saved circuits are stored in your browser.

Option B — with real quantum frameworks. Start the optional Python backend. It serves the site and the API on one port and runs circuits on Qiskit Aer, PennyLane, Cirq and qBraid:

pip install -r backend/requirements.txt
python backend/server.py
# open http://localhost:8000

The Lab detects the backend automatically (same origin, then http://localhost:8000). A custom URL can be set via the status pill in the Lab header.

Circuit Builder (drag & drop)

  • Place gates: drag from the palette onto a wire, or click a gate then click a spot (works on touch screens). Hold Shift while clicking to keep placing the same gate.
  • Edit: click a placed gate to open the inspector — change control/target qubits and angles (e.g. pi/4).
  • Move / delete: drag a gate to a new spot; drag it back to the palette, double-click it or press Delete to remove it. Ctrl+Z/Ctrl+Y undo/redo.
  • Gate set: H, X, Y, Z, S, S†, T, T†, P, RX, RY, RZ, √X, U, CX, CZ, CY, CH, CP, CRZ, SWAP, CCX, CSWAP, Measure, Barrier, Reset — 1 to 8 qubits.
  • Examples: Bell, GHZ, teleportation, Deutsch–Jozsa, Bernstein–Vazirani, Grover (2 & 3 qubits), QFT, phase kickback, QRNG and more.
  • Send to Code Lab converts the circuit into Qiskit, Cirq, PennyLane, qBraid or OpenQASM code.

Code Lab

A code editor with line numbers, live parsing, error markers and a Problems list (with fix hints). Supported syntax:

FrameworkUnderstood in the browser
OpenQASM 2 / 3qreg/qubit[n], creg/bit[n], qelib1 gates incl. u1/u2/u3/cu1, register broadcasting, measure a -> b and b = measure a, barrier, reset
QiskitQuantumCircuit(n[, m]), QuantumRegister, all gate methods above, measure, measure_all, lists/ranges as qubit args, variables, numpy/math constants, for loops; flags removed APIs (execute, from qiskit import Aer)
CirqLineQubit.range, named qubits, cirq.H/X/…/CNOT/CZ/SWAP/TOFFOLI/FREDKIN, rx/ry/rz(θ)(q), ZPowGate/CZPowGate, X**0.5, S**-1, .on(...), cirq.measure
PennyLaneqml.device(wires=n), qnode functions, Hadamard/Pauli/S/T/SX/RX/RY/RZ/PhaseShift/Rot/U3/CNOT/CZ/CY/CH/SWAP/Toffoli/CSWAP/controlled rotations, qml.adjoint, probs/sample/counts (observables inside expval are ignored)
qBraidPrograms that embed an OpenQASM string (program = """…""") or a Qiskit/Cirq circuit and call qbraid.transpile

Changing the framework dropdown converts a valid program to the new framework. Ctrl+Enter runs the code.

Simulation backends

BackendWith Python serverWithout server
Qiskit Aerqiskit_aer.AerSimulator(method="statevector"), statevector + shotsRuns on the in-browser statevector engine (ideal, noise-free — identical results) and says so in the Execution tab
PennyLanedefault.qubit, qml.state() + qml.counts
Cirqcirq.Simulator() simulate + run
qBraidQiskit circuit → qbraid.transpile(…, "cirq") → Cirq simulator. qBraid-hosted devices can be added via qbraid.runtime.QbraidProvider with a QBRAID_API_KEY
Browser engineJavaScript statevector simulator, up to 10 qubits, always available

Bit order. Qiskit is little-endian; Cirq and PennyLane are big-endian. The server maps qubits so every backend returns statevectors and counts in Qiskit order (right-most bit = q0), which is what makes the Compare backends view meaningful. backend/test_backends.py checks random circuits across all backends and the browser engine for statevector fidelity ≥ 1−10⁻⁶.

Environment variables: PORT (8000), HOST (127.0.0.1), QLENS_MAX_QUBITS (20), QLENS_SEED (reproducible shots), QLENS_DATA_DIR, ANTHROPIC_API_KEY, QLENS_TUTOR_MODEL.

Visualisations

  • Bloch spheres for every qubit (drag to rotate). Entangled qubits show their reduced state (partial trace): the arrow shrinks and the purity drops.
  • Probabilities & counts: exact probabilities next to measured shot frequencies, with hover tooltips.
  • State vector: amplitude, magnitude, phase (colour dial + degrees) and probability per basis state.
  • Execution: backend, where it ran, shots, time, gate count, depth, counts table, JSON download.
  • Step-through: the slider replays the circuit gate by gate, updating every view.
  • Backend comparison: the same circuit on every backend with total-variation distance and state fidelity.

AI Quantum Tutor

The tutor panel (Lab and Learning Hub) sees the current circuit, code, parse errors, active challenge and your progress. Built-in capabilities (no API key needed):

  • Concept explanations from a 29-topic knowledge base, with analogies and “Try it” circuits.
  • Explain my circuit — step-by-step state evolution, final state (recognises Bell/GHZ/uniform states), outcomes and entanglement.
  • Code generation — Bell, GHZ, superposition, QRNG, teleportation, superdense coding, kickback, Deutsch–Jozsa, Bernstein–Vazirani (any secret), Grover (any 2–3 bit target) and QFT, in any of the five frameworks, with one-click load.
  • Debugging & error detection — syntax/API errors with line numbers and fixes, deprecated APIs, gates after measurement, controls that never fire, unused qubits.
  • Optimisation — cancels inverse pairs, merges rotations, rewrites H·X·H→Z, S·S→Z, T·T→S, removes zero rotations; shows before/after gate count and depth and can apply the result.
  • Personalised recommendations from your quiz scores, weak topics and challenge history; hints for active challenges.

LLM mode: set ANTHROPIC_API_KEY before starting the backend and open-ended questions are answered by Claude with the same context. The key stays on the server. The original Botpress Quantum Assistant bubble on the home page is unchanged.

Assessments

  • Quizzes: 40 questions (5 per module) with instant per-question feedback and explanations; pass mark 70%; best score and attempts are kept.
  • Circuit-building challenges (12) and coding challenges (7), graded automatically by state fidelity, unitary (process) fidelity or output distribution, plus rule checks (allowed/forbidden gates, gate limits, measurement, loops).
  • Scoring: 100 for an optimal solution; −5 per gate above optimal (max −30); −10 per hint; minimum 50 when solved.

Progress tracking & personalised learning paths

Module progress = 50% lessons read + 30% quiz (full credit at ≥70%) + 20% challenges solved. A module is complete when all lessons are read and the quiz is passed.

The learning path is ordered by your goal (foundations, algorithms or coding) and your experience level marks earlier modules as optional review. Recommendations prioritise: quizzes to review (<70%) → weak topics (>40% wrong) → the module in progress (next unread lesson) → the next module → open challenges in modules you've mastered.

Instructor dashboard

Learners enter a class code under Dashboard → Join a class. With the backend running, progress syncs automatically; instructors load the class by code. Without the backend, learners export a progress file and instructors import many files at once. A sample cohort (clearly labelled synthetic data) is available for exploring.

Analytics: learner count and weekly activity, average completion, average quiz score, challenge pass rate, learners needing attention, module completion and quiz-score charts, hardest topics, per-challenge performance, a sortable roster with status (On track / Review / Needs attention / Inactive), per-learner drill-down with suggested next steps, and CSV export.

Saving & managing circuits

Save in the Circuit Builder stores the circuit with a name, description and tags under My Circuits: open, open as code, rename, duplicate, export (JSON), delete, search, import (.json or .qasm), export all. Share copies a link that encodes the circuit. When the backend is connected, saved circuits are mirrored to it.

Architecture

A static, framework-free front end (matching the original HTML/CSS/JS site) with modular scripts, plus an optional Python service.

learn.html · lab.html · dashboard.html · docs.html   new pages (same header, footer, styles)
assets/css/quantum.css      new components; reuses style.css variables
assets/js/qcore.js          circuit IR, gate library, statevector simulator, Bloch vectors,
                            metrics, optimiser, code generation (Qiskit/Cirq/PennyLane/qBraid/QASM)
assets/js/qparser.js        multi-framework parser → IR, with line-numbered errors & hints
assets/js/qcontent.js       modules, lessons, quizzes, challenges, examples, tutor knowledge base
assets/js/qstore.js         storage, progress, grading, learning paths, saved circuits, backend client
assets/js/qviz.js           Bloch sphere, charts, state table, circuit SVG, toasts, markdown
assets/js/qtutor.js         AI tutor engine + chat component
assets/js/lab.js · learn.js · dashboard.js           page controllers
backend/server.py           FastAPI: /api/simulate (4 frameworks), /api/tutor, class progress, circuits
backend/test_backends.py    cross-backend verification        tests/*.test.js   engine tests (Node)

Extending

  • New module / quiz / challenge: add an object to QL.MODULES or QL.CHALLENGES in qcontent.js — pages render from data.
  • New gate: def() it in qcore.js, add codegen/parser mappings and GATE_ARITY in the server.
  • New backend: add a run_x() function to RUNNERS in server.py and an entry in QL.BACKENDS.

Limitations & notes

  • Simulations are ideal (noise-free). Measurements are treated as terminal; reset in the browser engine is an approximation (exact on the Python backend).
  • The browser parser covers the common learning subset of each framework; full programs (custom functions, classical control) run on the Python backend.
  • Progress and saved circuits live in the browser unless the backend is used. The instructor view has no authentication — add your institution's login in front of the backend for production use.
  • The Celestial Toolkit simulators on Streamlit and the Botpress Quantum Assistant remain as before.
